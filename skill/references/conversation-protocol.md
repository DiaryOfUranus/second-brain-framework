# 对话级管理协议

> 来源：工程通论 §9.6, §9.9
> 用法：当需要细化对话管理流程、处理中断恢复、执行自动提取时加载。

## 五步对话结构

每次有实质工作的对话，按以下五步执行。这是工程通论 §9.6 的操作化。

### 步骤1：上下文加载

**做什么**：恢复上次对话的上下文，或确认这是新任务。

**怎么做**：
1. 检查 `{{HOME}}\WorkBuddy\<workspace>\.workbuddy\memory\MEMORY.md`（长期项目记忆）
2. 检查 `{{HOME}}\WorkBuddy\<workspace>\.workbuddy\memory\YYYY-MM-DD.md`（当日工作日志）
3. 检查 `~/.workbuddy/MEMORY.md`（跨项目用户偏好）
4. 检查当前任务相关的已有 skill（`~/.workbuddy/skills/` 和 `.workbuddy/skills/`）
5. 检查当前任务相关的已有知识库文件

**如果是续接对话**：
- 从工作日志中找到"当前进度"和"下一步"
- 如果进度记录清晰 → 直接从"下一步"继续
- 如果进度记录模糊 → 读取项目文件，对比上次记录，推断状态，向用户确认"我们上次做到X，现在继续Y，对吗？"
- 恢复后第一件事：验证上次的产出是否完整（文件存在？代码能跑？），再继续

**如果是首次对话**：
- 确认这是一个新任务
- 跳到步骤2

**完成标准**：能回答"我们上次做到哪了？下一步是什么？"（续接时），或"这是一个新任务"（首次时）。

**陷阱**：
- 不读工作日志就开始工作 → 可能重复已完成的步骤
- 读了工作日志但不验证上次产出 → 上次的文件可能不完整

### 步骤2：任务确认

**做什么**：明确当前对话要做什么。

**怎么做**：
1. 一句话定义任务：造物是什么？目标是什么？
2. 确认责任等级：
   - 1级（关键/安全）：做错了会危及人身安全或关键基础设施
   - 2级（重要/业务）：做错了会影响业务运行或造成经济损失
   - 3级（生产力/日常）：做错了会影响效率但不造成严重后果
   - 4级（个人/探索）：做错了只是浪费一点时间
3. 确认硬约束：不能碰什么？必须用什么？时间限制？
4. 确认执行模式：人主导AI辅助 / AI主导人验收 / 纯AI执行

**简化规则**：
- 如果是4级任务（个人/探索），可以内联确认，不必正式提问
- 如果是1-2级任务（关键/重要），必须显式确认，不能假设
- 如果是3级任务，根据复杂度判断

**完成标准**：任务定义清晰（一句话能说清），约束明确，责任等级已确定。

**陷阱**：
- 不确认责任等级就开干 → 验证严谨度可能不够（1级当4级做）或过度（4级当1级做）
- 忽略硬约束 → 可能触碰不可触碰的东西

### 步骤3：执行

**做什么**：按纪律执行任务。

**怎么做**：
1. 检查是否有专用 skill 覆盖当前任务
   - 有 → 加载并按 skill 流程执行
   - 没有 → 判断是否需要领域知识（如果需要，执行知识缺口检测流程）
   - 不需要领域知识 → 直接执行，但遵守工程公理约束
2. 执行中的纪律：
   - **先跑通再优化**：第一版目标是"端到端跑通"，不追求完美。优化针对已验证的短板，不针对想象中的短板。
   - **修改已有系统前先理解现有结构**：不要盲改。理解"为什么现在是这样的"再动手。
   - **每完成一个步骤 → 对照完成标准自检** → 通过则进入下一步
   - **修改代码/文件后 → 先自行验证无报错** → 再提交给用户
   - **不可逆操作 → 必须人工确认**（删除文件、发布内容、修改原始数据）

**AI自主权边界**：
- 可自主执行：信息获取、知识库构建、代码编写、格式调整、自检、版本保存
- 需要人确认：架构决策、品质基准、发布/交付、不可逆操作、方向性变更
- 绝不自作主张：删除人的文件、修改人的原始数据、对外发布未经人确认的内容

**完成标准**：产出已完成，自检已通过。

**陷阱**：
- 追求完美导致第一版迟迟出不来 → 先跑通再优化
- 不理解现有结构就改 → 可能破坏已有功能
- 代码改完不验证就提交 → 可能包含明显错误

### 步骤4：验收

**做什么**：产出提交给用户前，执行自检。

**怎么做**：
1. 对照任务定义：产出是否满足目标？
2. 对照约束：是否触碰了硬约束？
3. 对照质量门（见 SKILL.md 的质量门章节）：所有强制检查项是否通过？
4. 如果产出是文件 → 验证文件存在且内容完整
5. 如果产出是代码 → 验证能运行且无报错
6. 如果产出是文档 → 验证格式正确且内容覆盖任务要求

自检通过后提交。自检不通过 → 诊断问题 → 修复 → 重新自检。

**完成标准**：所有自检项通过，产出已提交给用户。

**陷阱**：
- 不自检就提交 → 可能包含明显错误
- 自检太粗（只看"有没有"不看"好不好"）→ 质量不达标

### 步骤5：状态更新与自动提取

**做什么**：更新工作日志，提取值得记住的信息。这是强制步骤，不可跳过。

**怎么做**：

1. **更新工作日志**：
   - 检查 `{{HOME}}\WorkBuddy\<workspace>\.workbuddy\memory\YYYY-MM-DD.md` 是否存在，不存在则创建
   - 追加本次工作摘要（做了什么、产出是什么、有什么发现）

2. **自动提取**（不等用户指示）：
   扫描本次对话，识别以下类型的信息：

   | 信息类型 | 识别信号 | 写入位置 |
   |---------|---------|---------|
   | 关键决策 | "我们决定了X""就用这个方案" | MEMORY.md 或工作日志 |
   | 新教训 | "这样做会出问题""原来X会导致Y" | 工作日志或对应 skill 参考文档 |
   | 用户偏好 | "我不喜欢Y""以后都用Z方式" | `~/.workbuddy/MEMORY.md` |
   | 新事实/新知识 | "发现了Z""原来X的原理是W" | 对应知识库或工作日志 |
   | Skill 使用教训 | 使用 skill 时发现的不足 | skill 的参考文档或工作日志 |

3. **判断标准**：如果下次对话不知道这条信息，会不会重复犯错或重复提问？
   - 会 → 写入
   - 不会 → 不写（不要把临时信息写入长期记忆）

**完成标准**：工作日志已更新，值得记住的信息已提取并写入对应位置。

**陷阱**：
- 忘记更新工作日志 → 下次对话无法恢复上下文
- 把临时信息当长期记忆写入 → 记忆文件膨胀，信号被噪音淹没
- 不主动提取，等用户说"记住这个" → 信息遗漏

## 中断恢复流程

### 检查点机制（防中断）

- 每完成一个有意义的步骤（不只是对话结束），更新工作日志中的"当前进度"
- 代码项目：每完成一个功能模块，保存一个版本快照
- 不要等到"全部做完"才保存——中途断电/断网/关窗口，损失最小化

### 中断恢复

1. 新对话开头，读工作日志，找到"当前进度"和"下一步"
2. 进度记录清晰 → 直接从"下一步"继续
3. 进度记录模糊 → 读取项目文件，对比上次记录，推断状态，向用户确认
4. 恢复后第一件事：验证上次的产出是否完整
5. 验证通过 → 继续
6. 验证不通过 → 修复上次的遗留问题，再继续

## 记忆管理纪律

- **存事实不存原文**：提取核心信息，不存整段原始数据
- **时间感知**：知识库条目必须标注日期。加载上下文时优先近期条目。超过3个月未被引用的条目标记"待审查"
- **主动提取而非被动等待**：不等用户说"记住这个"，在每次对话结束时主动识别值得记忆的信息
- **多信号检索**：查找历史信息时，同时用语义搜索和关键词匹配，不依赖单一检索方式
