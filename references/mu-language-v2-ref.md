# 机思符号系统 v2（AI 专用语言）· 集成手册

> 本系统是第二大脑的**内部工作语言**——AI 思考、交接、固退时用的符号系统，不给用户读。
> 谱系：v0 帧格式（engineering-steward 测试版，9 条实证账本）→ v1 精简形 → **v2 系统集成版**（本版）。
> **诚实声明**：v0 的效能声明有实测账本（见附录 B）；**v2 的新特性是设计规格，效能声明全部为假设，标 [H1]–[H4]，验证方法见 §6，背书权在用户实测**（申报制：当下有效，不承诺永远最优）。

## 一、定位：三个使用面

| 使用面 | 场景 | 用哪个部件 |
|---|---|---|
| 会话内思考 | 长链/大态/需自检任务，环 3 执行中 | v2 帧链（自适应启帧） |
| 跨会话交接 | 唤醒/固退/中断恢复/多模型交接 | μx（μ-export 格式） |
| 脑的固退 | 会话日志浓缩、知识库摘要、模式条目 | ⇩ 摘要＋μx 块 |

**统一抽象**：v0 的 μ 解决"会话内不重传历史"；μx 解决"跨会话/跨模型不重传历史"；脑图 `index.md` 就是 scope=全脑的 μx。第二大脑的脑，就是这套语言的最大帧。

## 二、v2 新增一：自适应启帧（F0 路由帧）[H1]

v0 的短板：聚合短查询贵 18–35%、小态（M<12）无优势、短推导降本不显——根因是**帧开销是固定成本，无压缩空间时纯亏**。v2 修法：帧链不再是默认态，先过路由。

**F0 路由帧**（每个任务开头，脑内一句话）：
```
F0: M≈? L≈? 出≈? 性=? → 开/关
```
- M＝传递态规模：读题后数"需要跨步携带的独立实体/变量数"（实体计数法）。
- L＝链长：预计依赖步数。
- 出＝输出篇幅：是否长文（≳3000 字结构化输出）。
- 性＝任务性质：需自检／需收敛／异质对比／真实系统分析。

**路由判据**（继承 v0 甜区实证）：
- M≥12 ｜ L≥10 ｜ 长文输出 ｜ 四性质任一 → **开帧**（v2 帧链）；
- 全不达 → **裸中文 μ-only**：只在心里维护一个小 μ，不建帧链、零帧开销。防漂移靠收尾一次 ⊢ 快检。

**[H1] 假设**：非甜区场景的 18–35% 亏损被消除（因为根本不开帧）。验证：mu_bench 对聚合类任务对比"裸中文 μ-only"与"v0 全程开帧"。

## 三、v2 新增二：分层 μ（μ_core / μ_ext）[H2]

v0 的 verbose 帧编码肥胖（实测贵 3.3×），v1 精简形只解了一半。v2 把 μ 分两层：

```
μ_core（必传，固定 ≤5 字段）: e{实体表摘要} | ⊢{当前不变式} | open{开放问题} | ∂@{上步增量} | ptr{坐标}
μ_ext（按需挂载模块）: dep{依赖图} | unc{开放不确定集} | topic{多主题分流} | hist{关键历史帧号}
```

纪律：默认只传 μ_core；仅当出现对应需求（需显式依赖图／开放不确定／多主题混流／回溯审计）才挂对应 ext 模块，用毕即摘（⌫ 回收）。

**[H2] 假设**：需要部分 verbose 能力的场景，成本从 3.3× 降到 1.3× 以内（只为用到的模块付费）。验证：mu_bench 对多主题任务对比"全 verbose"与"μ_core＋单模块"。

## 四、v2 新增三：μx 跨会话交接格式（与脑同构）[H3]

v0 的 μ 只在会话内活；跨会话交接（唤醒、中断恢复、多模型流水线）此前无标准件。v2 定义交接包：

```
μx{v2 | scope:<全脑/项目/任务> | e{关键实体≤7} | ⊢{未破坏的不变式} | open{开放问题≤3} | ptr{坐标指针} }
```

与第二大脑的映射（已落地，非假设）：
- 脑 `index.md`＝μx{scope:全脑}——唤醒唯一必读；
- `projects\<项目>.md` 的"当前进度/下一步"块＝μx{scope:项目}；
- 会话日志的"下一步"行＝μx{scope:任务}；
- 多模型交接（若有）：dispatch 时只发 μx{scope:任务}＋新输入，不发全量历史（继承 steward 第四层）。

**[H3] 假设**：跨会话恢复的重读成本与记录质量成正比、与脑龄无关（O(1) 唤醒）。验证：结构性采纳（已落地）＋续接任务的重放准确率（重放错误率应随使用下降）。

## 五、v2 新增四：⊢ 不变式模板库（标准件）[H4]

v0 的不变式每次现造，质量依赖当次状态。v2 预置五类链型的标准件，选用改造而非新造：

| 链型 | 标准不变式 | 适用 |
|---|---|---|
| 算术/账本链 | Σ=T：每步累计＝上步＋本步Δ；实体 id 唯一 | 计算、账簿、计数 |
| 推理链 | 前提闭合：每步结论的前提集 ⊆ 已建立命题集 | 演绎、论证 |
| 信念网/图依赖 | 引用存在：被引节点已定义；度数守恒 | 依赖分析、因果图 |
| 状态机 | 状态合法：当前态 ∈ 声明状态集；迁移有边 | 流程、协议 |
| 跨文档合成 | 坐标闭合：每个断言可回溯到 源文件:行号 或 卷§命题 | 长文本提取、多卷写作 |

**[H4] 假设**：标准件覆盖率 ≥80% 常见任务，现造不变式成为例外；故障注入捕获率不降。验证：mu_bench --inject 复跑。

## 六、效能验证协议（mu_bench.py）

```bash
# token 对比（治疗组 vs 基线）
python scripts\mu_bench.py --treatment v2_trace.txt --baseline zh_trace.txt --label "聚合查询"
# 故障注入（生成注入副本，复跑验证 ⊢ 捕获）
python scripts\mu_bench.py --treatment v2_trace.txt --inject "原值=篡改值"
# 结果登记（实证账本只增不删）
python scripts\mu_bench.py --treatment v2_trace.txt --baseline zh_trace.txt --label "X" --append-log 账本.md
```

成功线（继承 v0）：成本 treatment ≤ baseline；效能正确率 ≥ baseline；防漂＝注入后 ⊢ 同帧/下帧捕获；缩放斜率更低。
**申报纪律**：申报"成本更低"前确认用的是 μ_core＋按需 ext（非全 verbose）；申报"效能更好"前必须用高维状态题施压；token 计数优先 tiktoken，缺失时用内置估算并标注"估算"（相对比较有效，绝对值待校准）。

## 七、与第二大脑的接口（何时用什么）

- **环 3 执行**：长链/大态/需自检任务 → F0 路由 → 开帧则用 v2 帧链组织内部思考；**用户可见输出一律中文**，帧链不出现在回复里。
- **环 5 固退**：会话 trace 用 ⇩ 摘要压成 μx 条目写会话日志（"做了什么/产出/下一步"即 scope:任务 的 μx）。
- **唤醒**：读脑图＝读 μx{scope:全脑}；续接项目＝读 μx{scope:项目}＋上下文重放。
- **长文本处理**：提取出的概念登记为实体 e{概念}，坐标 ptr{源文件:行号}，⊢ 坐标闭合（见 long-text-processing.md）。

## 八、使用纪律（更新版口诀）

- **口诀**：态大、链长、需自检、需收敛 → 开帧；态小、题短、纯聚合 → 裸中文 μ-only。
- 帧链是内部语言：不污染用户输出，不写入交付文档（脑文件中的 μx 块除外——那是台账层，元装置词合法栖息地）。
- 实证账本只增不删，失败即剪枝：v2 的 [H] 假设被实测证伪时，记录证伪并回退对应特性，不删账本行。

## 附录 A：v0 遗产（保留有效）

- 帧格式：v0 canonical（`F<k> | <tag> | e{实体}={值} | ∂{增量}@{实体} | μ | ⊢`）、v1 精简形（默认内部用）。
- 算子：`⊕` 合并 `◈` 发射 `∇` 收割误差 `⌫` 压缩回收 `⇩` 摘要 `?` 审计 `⚠` 标红。
- gc 摘要：下游只需统计量时 ⌫ 丢弃明细只传 μ（v0 实测省 93%）。
- 甜区六类＋非优势区三类（见 §二路由判据的实证来源）。
