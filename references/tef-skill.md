# 超长理论提取—形式化工作流（theory-extract-formalize）· 子 Skill 使用手册

> **本文件是第二大脑（second-brain）受管子 Skill 之一**，由总管在「超长理论文献处理」类任务中按需加载。
> 适用场景：超长理论 → 脚本化提取（不灌上下文）→ 双标记合成 → 三分拆消解伪冲突。
> 本子 Skill 不再作为独立 skill 存在，其全部内容（含双标记规范、三分拆框架、提取脚本）已并入第二大脑。

---

## 1. 禁止项（风险优先）

- **禁止把超长原文整篇灌入上下文**：六卷/专著可达数万行，必须脚本化提取、只读取命中点，绝不用 Read 整卷。
- **禁止替作者下断言**：所有对原文的改写、构造性转写、推断必须显式标记为「草案转写」/「本项目推断」，且可回溯到原文落点（卷§命题）。作者原命题只能「登记」，不能「修订」。
- **禁止越界推进**：当原文把多个性质压进一个命题时，只能「识别并显式拆开」，不能替作者决定拆不拆——把决策作为待复核项交回。
- **禁止破坏原文文件**：提取是只读扫描，产出一律写入新建的项目目录，绝不修改源文献。
- **禁止在弱环宿主上用反例证伪 P1 类猜想**：若涉及「内部验证器/迭代效能」类命题，证伪实验必须控制宿主环强度（见 §4 三分拆）。

## 2. 工具依赖声明

- **Python 3**（受管运行时优先）：用于脚本化提取（`scripts/extract_theory.py`）。
- **ripgrep / grep**：快速统计命中分布（卷/章节级计数），用于侦察阶段。
- **可选 Lean 4 / Coq + mathlib**：仅当阶段 2 要实跑形式化内核时；若环境缺失，退到「可运行 Python 原型层」做演示（见阶段 2）。
- **Markdown 编辑器/预览**：产出为 .md 文档簇，便于人审。

## 3. 触发条件

满足以下任一即触发（总管据此加载本子 Skill）：

- 用户给出多份（≥2）长文档，要求抽取某概念/术语相关信息。
- 用户要求「建一个关于 X 的研究项目 / 知识库」。
- 用户说「理论太长」「上下文放不下」「这几卷读不完」，需要结构化处理。
- 用户要求把某段理论「形式化」「写规格草案」「做研究路线图」。
- 用户后续处理同系列其他卷/其他理论，模式与本子 Skill 一致。

> 优先级：专用领域 skill 优先于 本子 Skill 优先于 通用知识。若已激活更专用的 skill（如某理论自带 skill），本子 Skill 退居后台只做质量门约束。

## 4. 执行手册

### 步骤 0：侦察（不读全文，只计数）
**做什么：** 用 grep 统计目标术语在各文档的命中分布，定位概念重心。
**怎么做：**
1. 对主概念词、上位基座词分别 `grep -c` 统计。
2. 找出命中的文档/卷，判断概念是集中在少数卷还是分散。
**产出：** 命中分布表（文档 × 术语计数）。
**完成标准：** 能回答「概念集中在哪几卷、基座定义在哪」，且未对任何长文档做整篇 Read。
**陷阱：** 直接 Read 整卷 → 上下文爆炸。先计数，后定点。

### 步骤 1：脚本化全量提取（不灌上下文）
**做什么：** 用 `scripts/extract_theory.py` 把命中点（含行号+章节路径）写入项目目录。
**怎么做：**
1. 确定项目目录（默认源文献同目录下的子目录，或用户指定）。
2. 准备术语表（主概念 + 基座术语 + 近义词）。
3. 运行脚本：`python extract_theory.py --source 源目录或文件清单 --terms 术语表 --out 项目目录 --context 3`。
**产出：** `01_原文提取/文档_术语.md`（每段附 `file:line`）、`05_命中索引.md`、`06_章节大纲.md`。
**完成标准：** 所有命中术语均有带行号的独立摘录文件，且主对话上下文未载入任何长文档全文。
**陷阱：** 术语表漏近义词 → 漏摘关键段落。先用侦察结果补全术语表。

### 步骤 2：定点合成（只读命中点）
**做什么：** 读取 `01_原文提取/` 中的命中点原文，做概念合成。
**怎么做：**
1. 仅 Read 命中点摘录文件（已是小文件），不回灌全卷。
2. 对每个核心断言，用【原文登记】登记原文、【草案转写】写构造性/类型论转写。
3. 产出 `02_概念索引.md`、`03_研究路线图.md`、`04_待解问题.md`、`00_项目说明.md`。
**完成标准：** 概念索引每条均可回溯到「卷§命题」；待解问题全部标注原文出处。
**陷阱：** 把「草案转写」写得像原文 → 混淆作者意图。双标记不是装饰，是硬约束。

### 步骤 3：三分拆消解伪冲突（核心差异点）
**做什么：** 当发现作者原命题内部"矛盾"或"某条件是否必要"之争时，先判断是否为伪冲突。
**怎么做：** 参见 `references/tef-three-way-split.md`。核心动作：
1. 识别原命题是否把「可证伪的效率猜想 / 身份断言 / 隐藏前件」三件不同性质的东西压在一起。
2. 显式拆开：效率猜想条件组 `H_func`、身份断言组 `H_id`、隐藏前件 `Strong(H)`。
3. 把"是否拆分""某条件是否纳入本体"等决策作为待复核项交回作者，不擅自动摇定义。
**完成标准：** 表面冲突被定位为"三性质混淆"、给出显式拆分框架、并列出待作者裁定的残留项。
**陷阱：** 直接判定"某规格可推迟/可删" → 可能动摇身份定义。只拆不删，决策交回。

### 步骤 4：形式化草案（阶段 1）
**做什么：** 把核心规格转写为可机器检查的定义（见项目 `07_*.md` 范式）。
**怎么做：**
1. 基本对象构造性定义（介质三元组、凭证、验证函数）。
2. 逐条规格 → 构造性/类型论定义，严守双标记。
3. 可测算子（如迭代效能 `η_iter`）对齐作者自己的操作定义。
4. 证伪阈值算化，显式控制隐藏前件。
**完成标准：** 每条规格有【原文登记】+【草案转写】双标记；度量与主度量对齐作者定义；隐藏前件被显式化。
**陷阱：** `η_iter` 之类算子取错主度量（如用 `1/(N·r)` 而非「稳定结构数/(N·r)」）→ 用作者自己的操作定义校核。

### 步骤 5：实跑最小内核（阶段 2）
**做什么：** 把草案的信任内核 `K` 规则集从草稿填成可运行/可编译的骨架。
**怎么做：**
1. 若环境有 Lean/Coq：写真实骨架（structure/def，`sorry` 占位未证项），交作者编译。
2. 若环境缺失：写**可运行 Python 原型**实际演示六规格的内部验证信号与 `η_iter`，作为原型层（诚实标注层级）。
3. 演示"内部纠错信号"如何由跑一次 `K` 产生、组合性如何扩展验证、退编译图如何溯源。
**完成标准：** 至少一层（Lean 骨架 或 Python 原型）可产出"运行 K 一次即得到 Verify 结果"的端到端示例。
**陷阱：** 把原型当形式证明 → 必须标注"原型演示 ≠ 形式化验证"。

### 步骤 6：状态更新与自动提取（收口）
**做什么：** 更新项目 status、写工作日志，保证跨会话可恢复。
**怎么做：**
1. 在项目目录追加阶段进度（M1/M2…里程碑）。
2. 在 `~/.workbuddy/memory/` 或项目记忆写今日笔记。
3. 若发现本工作流本身可优化，记录到本子 Skill 参考文档或反馈 second-brain。
**完成标准：** 下一会话仅凭项目 `00_项目说明.md` + 记忆即可恢复上下文。

## 5. 质量门（验收检查清单）

- [ ] 未对任何长文档做整篇 Read（仅计数 + 读命中点摘录）。
- [ ] 所有产出写入新建项目目录，源文献未被修改。
- [ ] 每条【草案转写】均有对应【原文登记】与「卷§命题」回溯锚点。
- [ ] 任何推断/改写均显式标记，无伪装成原文之处。
- [ ] 若发现命题内部冲突，已用三分拆定位为伪冲突，并把拆分决策交回作者。
- [ ] 度量（如 `η_iter`）主度量已对齐作者自己的操作定义。
- [ ] 阶段 2 实跑物诚实标注层级（Lean 骨架 / Python 原型），未把原型当证明。
