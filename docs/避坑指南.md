# 避坑指南：反模式清单 · 统一报错风格 · 故障自恢复表

> 本指南回答三个问题：**哪些坑会反复踩（反模式）**、**报错应该长什么样（风格统一）**、
> **出问题后怎么自愈（恢复表）**。写给装了第二大脑的 AI 看——用户遇到问题时，
> AI 按本指南自动诊断与恢复，**用户不需要读它**。
>
> v0.3.3 新增（对应评测短板：反模式与 FAQ 4.4 / 异常处理 4.3 / 运行稳定性 4.3）。

---

## 一、反模式清单（每条：症状 → 根因 → 预防）

以下条目均来自本框架及其私有前身的**真实事故**（错题本只增不删纪律的脱敏沉淀），
不是理论推演。AI 在写文件、记台账、跑机检、做迁移时按此清单自查。

| # | 反模式 | 典型症状 | 根因 | 预防（机械件） |
|---|---|---|---|---|
| A1 | `open(p,"w")` 直写 | 文件被清空后写入中途失败，原内容全丢 | 打开即截断，无回退 | 原子写：先写 `.tmp` 再 `os.replace`（见 `scripts/ledger_writer.py` 的 `_write`） |
| A2 | 锚不唯一就插入 | 内容插错位置，台账乱序 | 用裸 `find`/子串匹配定位 | 整行相等锚＋命中数恰 1 断言（写器P-1） |
| A3 | 台账重复写入 | 同一条目出现两遍 | 无幂等键 | 内容指纹（fp）先查重，已在即 SKIP |
| A4 | 条目撞号 | `#N` 编号冲突，引用错乱 | 写前没查全档 | 写前断言 ID 全档唯一（含归档区） |
| A5 | 行尾混写 | CRLF 件被掺入裸 LF，diff 全文件爆红 | 落笔时未保持原行尾形态 | 归一→插入→还原＋写后行尾不变量断言 |
| A6 | 管道吞退出码 | `cmd \| tail -1 \|\| ok` 把远端失败吞成通过 | 判的是管道末端的退出码 | 落盘捕获输出 → 判命令自身 rc → 再校验成功标志 |
| A7 | 报成功≠已落地 | 工具回执 success 但持久层没变 | 把工具回执当事实 | 关键写入后回读复核（grep/Read）；交付说明与实物 sha 对表 |
| A8 | 自述即断言 | 文档说「13 条」实际只有 12 条 | 计数与实现不同源 | 计数要么 `len()` 生成、要么交付前回读；最稳是把自述变 `assert` |
| A9 | 凭 mtime/单一下断言 | 「mtime 没变＝没被迁移」判据失效（copy2 保时反例） | 判据面比想象窄 | 断言须声明「线别/树别/口径」；单一线索不定罪 |
| A10 | 批量替换误伤 | `str.replace` 全量替换改掉真坐标 | 无幅度闸 | 跨文件批量替换前跑幅度预算检查；逐处 `assert count==1` |
| A11 | 台账挂账无触发条件 | 「以后再说」= 永久挂账淤积 | 三栏制缺第三栏 | 无可判定触发条件不得登记（日期/次数/用户动作/文件出现） |
| A12 | 坐标凭记忆补全 | 引用行号与原文对不上 | 没回权威源实读 | 凡引用带坐标、回原文 grep 核验；大脑不改原文 |
| A13 | 自动推进里程碑 | AI 自作主张跨过应停等用户拍板的阶段 | 未区分「落库动作」与「里程碑」 | 落库/提交自主，里程碑/不可逆操作停等确认 |
| A14 | 收敛位私改第二套 | 公共件出现两个语义分叉的版本 | 想就地增强公共件 | 收敛＝逐字节采纳本体；差异登记走拟案管线，由本体侧升级 |
| A15 | 前手清单查前手漏 | 比对清单从产物结构生成，继承「漏」本身 | 让漏的人查漏 | 清单自底向上从原始材料侧生成（原件→「这条进来了吗」） |

## 二、统一报错风格（四段式）

本框架所有脚本的错误信息按同一风格输出——**说人话、给下一步、留逃生口**：

```
【发生了什么】一句人话，不用术语堆砌。
【为什么】    一句根因（知道多少说多少，不知道就直说）。
【下一步】    具体可执行的指令（命令或操作）。
【逃生口】    可回退路径或替代方案（如有）。
```

范例对照：

- ❌ 生硬：`AssertionError: anchor hits 2`
- ✅ 统一：`【发生了什么】插入锚「## 归档」在文件里出现 2 次，无法确定插哪。【为什么】锚必须全文件唯一才不会插错位置。【下一步】检查文件里重复的「## 归档」标题，改名其一后重试。【逃生口】本次写入未落盘（写前断言拦截），原文件完好。`

现状诚实声明：`scripts/ledger_writer.py`、`meta/brain_check.py`、`meta/run_all_selftests.py`、
`scripts/capability_briefing.py` 已按此风格；**存量脚本风格统一随版本渐进对齐**（各脚本的
报错已是人话+下一步，但四段式标签未全量贴齐——这是已知的渐进项，不是已完成时）。

## 三、故障自恢复表（症状 → 自检 → 自恢复 → 逃生口）

| 症状 | 先自检 | 自恢复动作 | 仍不行时 |
|---|---|---|---|
| 脑仓库报红/结构异常 | `python meta/brain_check.py`（只读） | 按红项提示逐条处理；黄灯可缓 | `git log --oneline -5` 找最近完好提交，`git checkout` 回滚 |
| 提交后机检没跑 | `ls .git/hooks/post-commit` 在不在 | `cp meta/hooks/post-commit .git/hooks/post-commit` 重装钩子 | 手动跑 `python meta/brain_check.py` 兜底 |
| 推送 GitHub 失败（网络波动/502/schannel 中断） | 先看报错是网络层还是权限层 | 等 1–2 分钟重试；`tools/doctor.py` 诊断连通 | 走 Git Data API 绕道（本仓 `meta/` 同款范式：blob→tree→commit→refs，带终态回读） |
| 写入中断/文件疑似截断 | `ls <file>.tmp` 是否残留 | `.tmp` 完整则手工 `os.replace` 恢复；不完整则从 git 恢复 | `git checkout -- <file>` 回上次提交（本表 A1 已保证提交前无损） |
| 台账没写进去/写重了 | 全档 grep fp 指纹 | 重跑写入：幂等键会 SKIP 已存在的；缺失的补写 | 用 `scripts/ledger_writer.py --selftest` 验证写器本身健康 |
| 机检全绿但结果可疑 | 对照本表 A6/A7 | 人工回读持久层实物（文件/git log），不信回执 | 在错题本登记新病历（只增不删），给检查器补一条能变红的反例 |
| 能力/组件说不清 | `python scripts/capability_briefing.py` | AI 自扫描重出简报 | `--json` 拿机读清单逐项核对 |

## 四、功能成熟度表（诚实标注，防「直接用会有小缺憾」）

| 档 | 组件 | 说明 |
|---|---|---|
| **稳定** | `meta/brain_check.py`（v1.2）、`meta/brain_commit.py`、`meta/export_second_brain.py`、`scripts/ledger_writer.py`、`meta/run_all_selftests.py`、`templates/` | 多实例长期在用，判据带负控自测 |
| **可用·渐进** | 统一报错四段式（存量脚本贴齐中）、references 全部手册 | 功能完整，细节随版本演进；用起来没问题，措辞可能迭代 |
| **实验** | `meta/experimental/`（如 honesty_lint）、`docs/experimental.md` 所列件 | 有真实实测背书，但判据面仍在收窄验证中；用于生产前请先跑其 selftest 并读该文件诚实边界 |
| **DRAFT 储备** | 未接线的储备件（各实例自定） | 明确标注未接线；装了不等于生效——按 `docs/experimental.md` 口径处置 |

> 判读规则：**凡未标「稳定」的组件，AI 应在代用户执行前先跑其 selftest／读其诚实边界**；
> 本表随每个版本更新，漏标视同「可用·渐进」。
