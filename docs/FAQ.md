# 常见问题（FAQ）与反模式清单

> 评测反馈里最集中的一点是「文档太密、缺通俗例子、不知道踩哪些坑」。这份 FAQ 就是补这个。

## 它是什么，一句话？

一套把 AI 自身当「认知主体」来养成的方法论 + 治理工具 + 机器可读 schema；落地为一个**本地 Git 仓库**（你的「脑」）和几个**零依赖 Python 脚本**。

## 和普通笔记 / PKM 工具（Obsidian、Logseq 等）有什么区别？

| | 普通 PKM | 第二大脑框架 |
|---|---|---|
| 定位 | 存放你写的内容 | 管理「AI 怎么做事」的纪律 + 你的结构化记忆 |
| 强制治理 | 无 | 坐标纪律、诚实边界、MEA 三权分立 |
| AI 协同 | 靠手动 | 协议化：启动声明、自动体检、候选·待证伪 |
| 可追溯 | 版本历史 | Git diff/回滚 + 错题本 + 审计账 |

简单说：PKM 是「仓库」，第二大脑是「仓库 + 管理员 + 纪律」。

## 什么时候该用？

- 你希望 AI 在**多次对话中记住**你的偏好、决定、项目上下文（而不是每次从头解释）
- 你做**有目的的创造活动**：写文章/代码/文档、分析/研究、构建系统/理论/产品
- 你重视**可追溯、可证伪、不幻觉**——需要 AI 引用带坐标、结论标候选

## 什么时候不该用？

- 纯闲聊、一次性简单查询（"今天天气""什么是 X"）
- 你只想快速要一个一次性答案，不愿维护任何文件
- 没有 Git / 不愿花 10 分钟初始化

## 装了之后每次对话都要做很多事吗？

核心只有两步，其余按需：

1. **开场声明**（一句话，记「已启动 / 未启动」）
2. **收尾提交**（跑 `brain_commit.py`）

红黄绿体检是 `post-commit` 钩子**自动跑**的，你不用手动。

## 那些「治理纪律」是强制的还是建议的？

框架把最关键的做成了**机械件**（脚本 / 钩子）：脑健康检查、命令护栏、提交自动化。但少数（如启动声明校验 `declaration_gate`）目前是**纪律级**（靠 AI 自觉调用），尚未 OS 级强制——这是已知的诚实边界，已在 `skill/SKILL.md` 标注，并非隐藏。

## 我必须懂「编译论 / 共振理论」才能用吗？

**不用。** 本开源包刻意**不含理论原文**，框架的方法论（五层协议、治理纪律、schema）可独立使用。理论基座是「进阶深度」，不是门槛。

## 我的数据会不会上传到云端？

**不会。** 纯本地 Git 仓库 + 零依赖脚本，不联网、不收集、不依赖任何第三方服务。开源是为了让社区审阅与共建，不是把你的脑搬上云。

## 反模式清单（踩坑必看）

1. ❌ **把模板当成品照搬**：模板里的 `{{占位符}}` 必须按本机实际填写；照抄示例值等于造了一个假脑。
2. ❌ **跳过启动声明**：没有「已启动 / 未启动」声明，后续记忆提取与审计会缺锚点。
3. ❌ **在私人脑里写死别人 / 别的机器的路径**：如 `C:/Users/某人/...`、别人的脑仓库路径。这是「实例化守卫」明确禁止的——互不改写彼此的脑。
4. ❌ **把「候选」当「已证结论」**：凡标注候选·待证伪的，未经验证前不要对外宣称落地。
5. ❌ **不装 post-commit 钩子**：导致 `brain_check` 不自动跑，红灯积攒成隐患。
6. ❌ **把本框架当一次性提示词**：它是持续运行的「OS」，不是粘贴即忘的 prompt。不维护就会退化。
7. ❌ **用 `git push -f` 强推私人脑**：不可逆操作，必须经人工确认（参考命令护栏思想，本包未内置强制，靠你自觉）。

## 遇到红灯 / 黄灯怎么处理？

`brain_check.py` 会打印每条检查的名称与状态。黄灯多为「尚未配置 / 尚未填写」，按提示补上即可；红灯会指出具体文件 / 字段，修完再提交。详见 `meta/brain_check.py` 顶部说明。

## 术语速查

- **MEA**：Manager / Executor / Auditor 三权分立，把「独立审计」焊进循环。
- **坐标纪律**：凡引用、凡精确命题、凡数字，必须带原文坐标；无坐标 = 待核验。
- **候选·待证伪**：一切命题先标为候选，可被证据推翻。
- **μ（充分统计量）**：跨会话 / 跨模型只传定长摘要，不重传全量历史。
- **GIR / CRL**：机器可读的「代际传承格式」与「编译权分布台账」schema（见 `schemas/`）。

## 我想把自己的脑脱敏后开源 / 分享？

用仓库自带工具：

```bash
python tools/assemble.py --check-only   # 先自检有无残留私人标识
python tools/assemble.py --git           # 生成干净副本（按需）
```

`tools/scrub.py` 负责占位符替换，`tools/assemble.py` 负责组装与校验。详见两脚本内注释。
