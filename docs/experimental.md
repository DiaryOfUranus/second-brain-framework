## 一、预言账本（前向差异流）· EXPERIMENTAL

### 定位

与后向差异流（failures 错题本）互补的一本新账：

- **错题本**测「已发生之事的偏差」——事后归因，只增不删；
- **预言账本**测「我对演进方向的推演偏差」——事前断言，到期对账。

引入它的动机：错题本只能让你不改过去的错，预言账本能让你**发现自己系统性
看偏的方向**——如果 6 个月预言全中，大概率不是你准，而是验证条件定太松
（预言学第一病）。

### 入账门槛：可证伪三道门（缺一不收）

1. **断言具体**——不许"会有所发展"类橡皮话；
2. **验证条件含可观察信号**——文件/公告/版本号/计数等可检索物；
3. **时间锚定**——明确验证窗口。

### 字段与偏差分类

每条记录：`ID / 领域 / 断言 / 预期时间 / 验证条件 / 依据 / 状态 / 偏差`。

「依据」栏必填（立账时点可见的证据）——没依据的预言不收，这是日后归因的锚。
偏差五类：

| 类 | 含义 |
|---|---|
| HIT | 命中 |
| DIR | 方向错 |
| TIM | 时机错 |
| MIS | 漏判 |
| FAN | 虚判（自我想象出的趋势） |

### 运行纪律

- **验证节奏**：固定周期对账（建议月度）；
- **回填只增不删，禁止改写原断言**——判错了就记 DIR/TIM/MIS/FAN，不洗；
- **自指条款（强烈建议）**：账本自己给自己立一条"账本将出现非命中记录"的
  预言——若长期全 HIT，判定为验证条件过松，须收紧三道门而非庆祝。

## 二、判据准入须附变异用例（B1）· EXPERIMENTAL

### 规则

凡**新增或修改**一条机检判据，须同批附上「**能使其由绿变红**的反例」
（变异用例），并在本轮实际跑出红——否则该判据不得登记为生效。

### 立法依据

「判据存在 ≠ 判据会触发」。实证：某检查器"不可解析 rev"分支因 git 对
无效 rev 返回**非零退出码＋空 stdout（并不抛异常）**，旧写法把空 stdout
当成 0，该分支**永不触发**——判据在册数月，实际从未拦住任何东西。
用例来源承 mutation testing（变异测试）思想：没杀死的 mutant = 无效测试。

### 操作化

1. 写判据时同步写反例（脏样本/坏输入）；
2. 跑判据 × 反例，确认命中（红）；
3. 跑判据 × 正例，确认不误报（绿）；
4. 两态读数随判据一起登记。

注意测试自身的清洁：`cmd | head` 后取 `$?` 判的是 **head** 的退出码——
先把"器无辜、测试脏"的假读数排除，再判判据有效性。

## 三、转正判据（从 EXPERIMENTAL 毕业的条件）

| 条目 | 转正条件 |
|---|---|
| 预言账本 | 连续 ≥2 个验证周期实际执行对账，且 ≥1 条非 HIT 或自指条款触发收紧动作 |
| B1 变异用例 | 在 ≥2 次真实判据新增中被执行，且至少 1 次红翻转实际拦住无效判据 |
| honesty_lint（meta/experimental/） | 判据面扩宽（当前 W1 对裸百分比不命中，见脚本头注）＋误报率实测数据 |
